# 도우미 봇 기능 계획 (2026-11-03)

## 빠른 시작 (실제로 진행하는 범위)

아래 본문 중 구현이 복잡하거나 무거운 것은 빼고 이 범위로 시작한다(11/03 결정).

| 순서 | 할 것 | 뺀 것 |
|---|---|---|
| 1 | 위키 일반 문서를 영어 원문 그대로 섹션 조각으로 넣고, 이름 사전으로 한국어 이름과 연결. 갱신은 전부 다시 받기 | 큰 표 두 개(Sell Values, Longwings) 해석, 한국어 번역, 변경분만 받기 |
| 2 | 플레이어별 최근 대화 3개 기억(30분 지나면 비움), "그거/이거" → 직전 이름을 검색에 더함, `/askforget` | 기억 압축(요약) |
| 3 | 손에 든 아이템, 인벤토리 목록, 날씨, 게임 날짜·시각, 계절, 바이옴, 차원 | 근처 구조물 |
| 4 | 팀 공유 (FTB Teams 파티 → 스코어보드 팀), `/askteam on\|off` | – |
| 5 | NIM·Gemini가 `tools`를 지원할 때만 `search_docs`, `read_page` (질문당 2번, 30초) | 위키 사이트 실시간 검색, 일반 웹 검색, 임베딩 검색, 도구 미지원 시 흉내 내기 |

지금 상태:
- `/ask`, `/q`, `/askmodel`이 동작한다.
- LLM은 NIM → Gemini → 로컬 순서로 폴백한다.
- 서버 자료(퀘스트, 농업연감, 상점, 실제 레시피)로 RAG를 한다.

이 문서는 다음에 붙일 기능 다섯 가지의 계획이다. 개념 설명은 [rag-concepts.md](rag-concepts.md)에 있다.

## 진행 순서

| 순서 | 기능 | 바꾸는 곳 | 서버 재시작 |
|---|---|---|---|
| 1 | 위키 자료 넣기 | 사이드카 | 필요 없음 |
| 2 | 대화 기억 + 후속 질문 처리 | 사이드카 | 필요 없음 |
| 3 | 플레이어 상태 넣기 | KubeJS + 사이드카 | 필요 |
| 4 | 팀원에게 답 공유 | KubeJS | 필요 (3번과 한 번에) |
| 5 | 검색 도구 (질문당 횟수 제한) | 사이드카 | 필요 없음 |

1·2번은 서버를 끄지 않고 할 수 있다. 3·4번은 KubeJS를 바꾸므로 재시작 한 번에 묶는다.

## 1. 위키 자료 넣기

**출처**
- 선릿 밸리 공식 위키 https://sunlitvalley.miraheze.org (영어, CC BY-SA 4.0)

**수집 (11/03에 받아 둠: `data/wiki/raw.json`)**
- 일반 문서 150개, 위키 문법 포함 95만 자.
- 빼는 것:
  - 넘겨주기 문서 5개
  - Cobblemon 변형 팩 문서 5개 (이 서버와 다른 팩)
  - 기여 안내 같은 위키 운영 문서
- 큰 표 문서는 따로 처리한다. 'Sell Values'(28만 자)와 'Longwings'(20만 자) 두 개다.
  - 글 조각으로 넣지 않고, 표를 읽어 아이템별 사실로 바꾼다.
  - 예: 판매가는 "아이템 정보" 카드에 "판매가: 128 (위키 기준)"으로 붙인다.
- 갱신은 `python3 -m askhowto wiki`로 수동으로 한다. 바뀐 문서만 다시 처리한다(문서마다 수정 시각을 저장).

**가공**
- 위키 문법을 걷어 내고 섹션(`== 제목 ==`) 단위로 조각을 나눈다.
- 문서 제목과 영어 아이템·NPC 이름을 이름 사전(`names.jsonl`)과 연결해 한국어 이름으로도 걸리게 한다.
  - 예: "Caroline" 문서 = 캐롤라인
- 출처 표시는 "위키 › 문서 이름 › 섹션"으로 한다.

**서버 자료와 다를 때**
- 위키는 팩 버전이 다를 수 있다.
- 서버 파일에서 뽑은 자료(상점 가격, 레시피, 제철)를 우선한다. 답변 규칙에 "위키 내용은 (위키 기준)으로 표시"를 넣는다.

**정할 것**
- 언어 처리 방식: 영어 원문을 그대로 넣을지, 한국어로 옮겨 넣을지. [rag-concepts.md](rag-concepts.md) 5장에서 고른다.

**평가**
- 위키에만 있는 내용을 묻는 질문 10~15개를 `tests/eval.py`에 더한다.
- 예: 초반 공략 순서, 우정(Friendship), 피시 폰드 사용법.

## 2. 대화 기억 + 후속 질문 처리

**저장**
- 플레이어(UUID)마다 `data/memory/<uuid>.json`에 저장한다.
  - 최근 대화 n개(질문, 답, 나온 아이템 이름)
  - 기억 요약 1개
- 기본값 n = 3.

**프롬프트에 넣는 방식**
- **최근 대화:** 클라우드 모델은 n개 그대로, 로컬 Gemma는 직전 1개만.
- **기억 요약:** n개를 넘은 오래된 대화는 LLM이 1~2줄로 요약해 "기억 요약"에 합친다(압축). 요약 호출은 답한 뒤에 하므로 답이 늦어지지 않는다.
- 30분 넘게 질문이 없으면 새 주제로 보고 최근 대화는 비운다. 요약은 남긴다.

**후속 질문 처리 (가장 중요)**
- "그거 어떻게 만들어?"는 질문만으로 검색하면 아무것도 못 찾는다.
- 질문에 지시어(그거·이거·저거·거기·걔)가 있거나 이름이 하나도 없으면, 직전 대화에 나온 아이템 이름을 검색어와 이름 매칭에 더한다.

**명령**
- `/askforget`: 내 기억 지우기 (KubeJS 명령 추가라 3번 재시작 때 같이 넣는다. 그전에는 사이드카에서 수동 삭제)

**로그**
- `qa.jsonl`에 기억을 썼는지 남긴다.

## 3. 플레이어 상태 넣기

**수집 (KubeJS, 질문할 때 한 번)**
| 항목 | 내용 | 비고 |
|---|---|---|
| 손에 든 아이템 | 주 손·보조 손 | "이거 뭐야?"의 "이거" |
| 인벤토리 | 핫바 9칸 + 많이 가진 아이템 상위 10개 (이름·개수) | 아이템 ID → 한국어 이름은 사이드카가 사전으로 바꾼다 |
| 날씨 | 맑음·비·뇌우 | |
| 게임 시간 | 날짜(몇 일 차), 시각(오전 7시) | |
| 계절 | Serene Seasons 현재 계절·단계 | 서버 스크립트가 이미 쓰는 API (`seasonSync.js`) |
| 바이옴·차원 | 바이옴 ID → 한국어 이름 | |
| 근처 구조물 | 지금 서 있는 구조물 (마을 등) | 가장 무거운 항목. 먼저 성능을 재 보고, 느리면 뺀다 |

**프롬프트**
- "[플레이어 상태] 질문과 관련 있을 수도, 없을 수도 있다. 관련 있을 때만 참고한다." 블록으로 넣는다. 약 200토큰 늘어난다.

**활용**
- 지시어 "이거/이것"이 있고 질문에 다른 이름이 없으면, 손에 든 아이템의 정보를 확정 정보로 붙인다(2번의 지시어 처리와 같은 규칙).

**보안**
- 좌표는 넣지 않는다. 바이옴·구조물 이름까지만 넣는다.

## 4. 팀원에게 답 공유

**팀 판정**
- FTB Teams 파티를 먼저 본다(서버에서 쓰는 중, 예: "버러G들").
- 파티가 없으면 바닐라 스코어보드 팀을 본다.
- 혼자인 개인 파티는 공유하지 않는다.

**보이는 모습**
- 접속해 있는 팀원에게 `[도우미] lota09님의 질문: …` 한 줄, 같은 답, 폴백 안내를 보낸다.
- [도움됨]/[틀림] 버튼과 "생각 중..." 메시지는 질문한 사람에게만 보낸다.

**끄기**
- `/askteam on|off`: 팀원 답 받기를 끈다. 플레이어 데이터에 저장한다. 기본은 켬.

**구현**
- KubeJS만 바꾼다. 사이드카는 그대로다.

## 5. 검색 도구 (횟수 제한)

**언제 쓰나**
- 처음 넣은 자료로 답하기 부족하다고 모델이 판단할 때만 도구를 부른다.
- 클라우드 모델(NIM, Gemini)만 쓴다. 로컬 폴백은 지금 방식 그대로다.

**도구**
- `search_docs(검색어)`: 서버 자료와 위키 색인 검색. 한국어 이름은 사전으로 영어 이름도 같이 찾는다.
- `read_page(제목, 섹션)`: 위키 문서의 한 섹션 읽기.
- `wiki_search(검색어)`: 위키 사이트 자체 검색 API (무료, 키 없음). 로컬 사본에 없는 최신 문서용.
- 일반 웹 검색(마인크래프트 위키 등)은 검색 API 키가 필요해 나중으로 미룬다.

**제한**
- 질문당 도구 호출은 최대 2번, 전체 30초.
- 넘으면 그때까지 모은 자료로 답한다.

**확인할 것**
- NIM glm과 Gemini OpenAI 호환 주소의 도구 호출(`tools`) 지원 여부와 형식.
- 지원하지 않으면, 모델이 정해진 형식으로 검색어를 출력하게 하고 사이드카가 실행하는 방식으로 바꾼다.

**안전**
- 도구는 읽기만 한다.
- 웹에서 가져온 글은 자료로만 다루고 지시로 따르지 않는다.
- 기존 보안 질문 차단은 그대로 둔다.

**평가**
- 첫 검색이 놓치는 질문을 모아 도구가 있을 때와 없을 때를 비교한다.
- 늘어난 응답 시간도 함께 기록한다.

## 공통 위험과 대응

| 위험 | 대응 |
|---|---|
| 넣는 자료가 늘어 답이 느려짐 | 서비스별 글자 예산은 그대로 두고, 기억·상태 블록은 크기 상한을 둔다 |
| NIM 무료 정책 변경, Gemini 혼잡 | 기존 폴백 순서 유지. `qa.jsonl`의 `fallbacks`로 빈도를 본다 |
| KubeJS 변경으로 서버 문제 | 3·4번을 한 번에 묶어 재시작. `/reload`는 쓰지 않는다 |
| 위키 내용이 서버 버전과 다름 | 서버 자료 우선, "(위키 기준)" 표시 |
