# 계획 1~5번 구현 결과: 테스트, 피드백, 수정 계획 (2026-11-03)

범위는 [plan-2026-11.md](plan-2026-11.md)의 '빠른 시작'이다(근처 구조물, 기억 압축, 번역, 웹 검색 등은 뺌).
판단 기준은 "원하는 결과가 안 나오면 모델이 아니라 도구(검색·자료·규칙) 탓"이다. 수정 계획도 모두 도구 쪽이다.

| 3 | 플레이어 상태(손, 인벤토리, 날씨, 날짜·시각, 계절, 바이옴, 차원). '지금·여기' 질문은 계절·바이옴으로도 검색 | `kubejs/askhowto.js`, `state.py` | 서버 재시작 필요 |
| 4 | 팀원에게 질문·답 공유 (FTB Teams 파티 → 스코어보드 팀), `/askteam on\|off` | `kubejs/askhowto.js` | 서버 재시작 필요 |

테스트하면서 바로 고친 것:
- **이름 자체는 못 만들지만 같은 계열은 만들 수 있을 때**(물뿌리개 → 구리~이리듐 물뿌리개) 계열의 만드는 법을 함께 넣는다. 계열은 레시피 재료 사슬로 등급 순서를 맞춘다.
- **'지금 계절에 심을 작물'**은 첫 검색이 계절을 몰라 도구까지 써서 32초가 걸렸다. 상태의 계절을 검색어에 더해 8초가 됐다.
- **답에 "[확정 정보]에 따르면" 같은 내부 표시가 새던 것**을 막았다.
- **NIM 빈 답 1건**: 추론에 출력 한도를 다 쓴 것으로 보여 NIM 출력 한도를 1000에서 2000으로 늘렸다.

## 2. 테스트 결과

### 2.1 전체 평가 (`tests/eval.py`, 93문항, 기본 순서 NIM → Gemini → 로컬)

| 시점 | 분류 | 사실 포함 | 응답 시간 (LLM 쓴 문항) |
|---|---|---|---|
| 위키 넣기 전 (12,000자 자료) | 89/89 | 29/31 | 평균 7.6초 |
| 위키 넣은 뒤 | 92/93 | 33/34 | – |
| 최종 (기억·상태·도구 포함) | 92/93 | 31/34 | 평균 8.3초, 중앙값 5.9초, 상위 10% 20.5초, 최대 49.5초 |

- 93문항 중 78개를 NIM이 답했다. 나머지 15개는 정해진 답(보안 거절, 잡담)이라 LLM을 부르지 않았다. 폴백은 없었다.
- 도구 호출은 1번뿐이었다("튤립 제철"). 평가 문항 대부분이 첫 검색만으로 풀린다.
- 토큰: 질문당 입력 약 2,900, 출력 약 140.

### 2.2 E2E 시나리오 (`tests/e2e.py`, 요청 파일 → worker → 응답 파일)

| 시나리오 | 결과 |
|---|---|
| 정동석을 들고 "이거 어따 써?" | 손에 든 정동석으로 이어져 파쇄망치 사용법을 답함 (3초) |
| "캐롤라인은 누구야?" → "걔한테 뭘 선물하면 좋아해?" | '걔' = 캐롤라인. 위키의 선물 목록, 4일마다 1회, 5하트 보상을 답함 |
| "물뿌리개 업그레이드?" → "어떻게 만들어?" | 등급별 만드는 법을 순서대로 답함 (수정 전에는 "만들 수 없어요") |
| 여름·비·밀 64개 상태에서 "지금 계절에 심을 작물" | 여름 작물 목록과 가진 밀 씨앗 활용을 답함 (8초) |
| 같은 상태에서 "엔더 드래곤 잡는 법" | 상태 내용을 끌어오지 않고 서버 메시지("엔드에 갈 수 없는 것 같다")와 바닐라 방법을 답함 |
| "Tiny Gnome은 어디서 얻어?", "우정 레벨 올리면 뭐가 좋아?" | 사전·위키로 바로 답함. 도구는 쓰지 않음 |
| `/askmodel local`로 같은 "이거 어따 써?" | 로컬 Gemma도 손에 든 아이템으로 답함 (도구 없음) |
| 대화 후 `/askforget` → "그거 어떻게 해?" | 기억이 지워져 '그거'를 잇지 않고 다시 물어봄 |

### 2.3 검증하지 못한 것
- **KubeJS 쪽(상태 수집, 팀 공유, `/askforget`, `/askteam`)은 실제 서버에서 돌려 보지 못했다.** 기기 재부팅(15:17)으로 서버가 꺼져 있었다.
  KubeJS가 쓰는 Rhino 파서로 문법만 확인했다(`tests/check_kubejs.sh`). 오류 문법을 넣으면 실제로 잡히는 것도 확인했다.

## 4. 수정 계획 (우선순위 순)

| 순서 | 대상 | 할 일 | 확인 방법 | 서버 재시작 |

| 2 | F1 | 채팅 글자 상한을 서비스별로 둔다(클라우드 700자, 로컬 450자). 프롬프트의 "3~4문장"도 같은 길이로 맞춘다. 잘릴 때는 마지막 줄에 "…(길어서 줄였어요)"를 붙인다 | "초반 계획"류 문항 통과, 채팅에서 길이 확인 | 아니요 |
| 3 | F2 | 이름 하나가 여러 종류(NPC·블록·아이템)를 가리키면 확정 정보 맨 앞에 "'노움' = 마을 주민 NPC / 장식 블록 / 작은 노움 아이템. 질문 맥락으로 고를 것"을 자동으로 넣는다. 질문에 '마을·주민·NPC'가 있으면 NPC 카드를 먼저 둔다 | 노움 문항 통과, 같은 이름을 쓰는 다른 문항 회귀 확인 | 아니요 |
| 4 | F3 | '게임 용어 점수'(분류를 건너뛰는 기준)는 한국어 토큰과 서버 자료로만 계산하고 위키 영어 토큰은 뺀다. 이름 매칭으로 걸린 위키는 그대로 둔다 | 영어 일반 질문이 OTHER로 돌아오는지, 영어 아이템 이름 질문(Geode 등)은 그대로인지 | 아니요 |
| 5 | F7 | 서버를 켤 때 실서버 확인 체크리스트를 돈다: KubeJS 로그에 `[ASKHOWTO] state` 경고가 없는지, `/askmodel`·`/askforget`·`/askteam` 자동완성, 파티원 두 명으로 공유와 평가 버튼(질문자만), `qa.jsonl`의 `state` 내용 | 체크리스트 | 예 (이미 설치됨) |
| 6 | F4 | 도구 효과를 잴 문항 세트를 따로 만든다: 첫 검색이 놓치는 질문(위키 섹션 깊숙한 내용, 여러 아이템을 엮는 질문). 도구 있음/없음을 비교한다. 꽃처럼 계절 태그가 없는 작물류는 아이템 카드에 "계절 제한 없음(계절 태그 없음)"을 넣는다 | 새 세트에서 도구 있음이 더 많이 맞추는지, 늘어난 시간 | 아니요 |
| 7 | F5 | NIM 시간 제한을 90초에서 40초로 줄여 느릴 때 빨리 Gemini로 넘긴다(Gemini 혼잡이면 로컬). `qa.jsonl`의 `seconds`·`fallbacks`로 일주일 분포를 보고 조정한다 | 상위 10% 응답 시간, 폴백 비율 | 아니요 |

1~4번과 6~7번은 사이드카만 고치면 된다. 5번은 이미 설치된 KubeJS를 다음 서버 시작 때 확인하는 일이다.

새로 나온 문제:
- **F8 Gemini 분류가 늘 '게임 질문'**: 출력 3토큰이면 Gemini가 빈 답을 내서 일반 질문이 전부 게임 질문으로 갔다 → 20토큰으로 고침.
- **F9 NIM glm 사용 한도**: 오늘 평가를 여러 번 돌려 glm만 429(같은 계정의 다른 모델은 됨). 2시간 넘게 풀리지 않아 하루 한도로 보인다. 폴백으로 Gemini가 답한다.
- **F10 실서버 첫 테스트에서 답이 안 옴(가장 큼)**: KubeJS가 게임 시각을 NaN으로 보내(`level.dayTime` 속성이 없음) 사이드카가 요청마다 죽었다.
  플레이어는 시간 제한 3분까지 기다렸다. → 상태 값 검증(이상하면 그 항목만 뺌), 처리 중 오류는 바로 오류 답을 보내고 계속 동작,
  KubeJS는 `level.getDayTime()`으로 고침(다음 서버 재시작 때 반영).

남은 일:
- 플레이어 접속 상태로 팀 공유·상태 수집 확인.
- NIM 한도가 풀린 뒤 93문항 전체 평가를 다시 한다(이번 회귀 평가는 NIM 한도와 세션 중단으로 끝까지 못 돌림).
- 한도에 걸린 서비스는 일정 시간 건너뛰어 매번 실패 안내가 붙지 않게 하기.
